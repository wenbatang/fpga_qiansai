# 四键风格切换与完整源帧

这是独立工程 `uart_style_keys`。原工程 `uart_style_hdmi` 和所有旧训练参数保留。用户已反馈旧版在板上能够转换；新版本的实际显示、按键行为和完整上传时间需要另行上板记录，不能把旧反馈当成新版本验收。

| 板上按键 | FPGA 输入 | 封装引脚 | 风格槽 | 功能 |
|---|---|---|---|---|
| KEY1 / K1 | sys_rst_n | D26 | — | 原复位功能 |
| KEY2 / K2 | style_keys_n[0] | J26 | 0 | 梵高《星月夜》 |
| KEY3 / K3 | style_keys_n[1] | E26 | 1 | 浮世绘《赤富士》 |
| KEY4 / K4 | style_keys_n[2] | G26 | 2 | 水墨国画 |
| KEY5 / K5 | style_keys_n[3] | H26 | 3 | 彩色油画 |

依据对应 FMC 原理图第 4、11 页，五个按键均接 Bank14，Bank14 电源 3.3V，按键松开由外部 4.7kΩ 上拉，按下接地。四个新增端口均为 **LVCMOS33 输入**，无驱动、无电源/DDR 参数变更。KEY2 另外由厂商 `01_key_led` 的 J26 约束交叉核对。实现后应检查全部 **88 个端口**，不仅是新增四个。

`style_keys` 在 100MHz UI 域使用带 ASYNC_REG 的两级输入同步，再对稳定状态计数 1,000,000 拍（10ms）消抖。按下产生一次脉冲，松开后才能再次触发；复位时长按的键必须先松开。同时按下多个键时 KEY2、KEY3、KEY4、KEY5 依次优先。约束仅切除外部按键到同步器首级的异步路径，级间路径仍检查。

`style_key_control` 保存所选风格、完整原图标志和源帧编号；启动时把风格锁到 engine_style。推理过程中改变请求风格不会改变正在运行的权重。忙时连续按键只保留最后一次请求，当前转换完成并换帧后再处理。默认风格是槽 0 星空。图片尚未上传时可以预选风格，但不会读取未初始化的 DDR。

原图位于 DDR `0x00400000`，风格图使用 `0x00000000` 和 `0x00200000` 双缓冲。每次按键直接重读完整原图、写入显示后台，最后一个 AXI B 响应成功后发起显示提交，显示读取器在安全垂直消隐窗口交换前后台。源帧编号始终保持一致；失败保留原前台，完整原图仍可重试。

UART 的 BEGIN 在推理占用总线时返回状态 4（忙）；此拒绝不会使完整原图失效。允许的新 BEGIN 则立即使旧原图标志失效，再接收数据，避免半帧被按键读取。CRC 失败、超时、ABORT 均不会重新标记该半帧为完整。下一帧只有在 END 检查整帧 CRC、全部写响应完成后才可交给 CNN。

串口仍传原始 RGB565、小端、逐行、无 padding；请求 COBS、ACK SLIP、2Mbps、最大包 16KB。命令 6 STYLE 在新工程返回状态 1，GUI 不发送它。命令 7 读最近一次完成推理的周期数；按键可能在上传结束后再次触发转换，该读数不能用来推断实际屏幕当前风格。上传 END 的 ACK 只属于上传作业，按键作业不会制造额外 UART ACK。

上传耗时与本地切换耗时分别计量。10ms 消抖、CNN+DDR 处理和等待垂直消隐共同组成按键切换延迟。HDMI 一直以 720p60 刷新完整前台，不代表神经网络每秒处理 60 张新图。
