# 主机摄像头自动拍照上传

用户已授权使用主机摄像头连续采集、自动上传完整原始像素图片，并支持停止。现有 Xilinx `uart_style_keys` 两套已签核 bitstream 可直接使用，FPGA RTL、权重和引脚没有因本功能改变。

## 运行

```powershell
cd F:\fpga_qiansai\xilinx\projects\uart_style_keys
python -m pip install -r pc/camera/requirements.txt
python pc/camera_gui.py
```

选择实际串口、2Mbps、与已下载bitstream一致的配置。720p输入1280×720，VGA输入640×480、HDMI仍720p60居中显示。相机默认编号0、DSHOW后端；打不开时可尝试实际摄像头编号、MSMF或AUTO，检查连接与系统摄像头访问设置。打开窗口不启动摄像头或串口，点击“开始自动采集与上传”后才打开。

相机分辨率是驱动实际返回值，不假装设置已被设备接受。OpenCV返回BGR，转换成RGB后等比缩放并补黑边，打包成RGB565小端、逐行、无padding，输出严格保持所选bitstream尺寸。相机不支持720p时，软件放大/补边输出720p；不会把协议尺寸悄悄降为VGA。

CLI支持Ctrl+C停止：

```powershell
python pc/camera_sender.py --port COM29 --profile 720p --camera 0 --backend DSHOW --interval 2
```

将COM29换成实际UART端口。`--frames 3`只传3张；不指定则持续传输。`--capture-fps`默认15，是读取节奏上限，不能当作串口更新FPS或板上推理FPS。

## 工作流程

1. 采集线程独占相机句柄，持续读取，只保存一个最新画面槽；预览和发送取得独立副本，旧采集帧主动跳过，不排成无限队列。
2. 上传线程独占一个串口连接和Link，每次只有一张在途。上一次完整END ACK及可选推理计数读取结束后，才取最新照片。
3. 沿用COBS请求、SLIP ACK、16KB停等包、CRC、偏移检查和重试。每张先ABORT建立新会话，再BEGIN/DATA/END；不发送风格命令、不做JPEG/PNG硬件解码。
4. FPGA收到完整源图后使用当前按键风格转换，等待最后AXI写响应和安全消隐换帧后返回END ACK。
5. GUI只有收到END ACK才增加完整照片数量；DATA进度100%还不表示已经转换/发布。推理计数为最近一次完成作业，可能来自板上按键再处理，不能保证它就是当前上传帧的作业。
6. ACK后默认停留2秒，方便观察和按键切换；期间及上传时继续采集新图，下一次仅取最新一张。GUI线程只处理预览、状态和事件，不阻塞于串口等待。

四风格参数不变：KEY2星空、KEY3浮世绘、KEY4水墨、KEY5油画；下一张照片沿用最近选择。上传新源图期间原图有效标记为0，按键请求可以预选，完整上传后再转换，禁止处理半张图。

## 两种停止

- **本张完成后暂停**：完成在途照片的CRC、转换和END ACK后关闭串口与相机，不发下一张。DDR源图仍完整，适合继续按键比较同一张照片。
- **立即停止**：尽快结束发送/等待并关闭串口，丢弃OS待发队列；之前已发布的图像继续显示。若新源图只传了一半，源图保持失效，按键不能重新转换，需下次完整上传。已经完整提交的图像可能继续在FPGA转换和显示，停止不回滚。

正常串口读取轮询20ms，写超时3秒；停止会等正在进行的底层写返回。相机驱动若阻塞，等待释放最多3秒后报错，未释放前禁止另开同一采集对象；关闭GUI可结束进程。设备断开或通信错误会退出本次自动上传，记录原因、关闭资源，用户重新开始时建立新会话，不无限重试错误设备。

## 速度与验证

2Mbps、8N1，720p RGB565裸像素线速预算9.216秒/张；VGA预算3.072秒/张。另有协议、USB、软件、FPGA推理和消隐等待，默认还加2秒停留。因此这里是连续自动拍照更新，不能称为15fps串口视频。HDMI持续60Hz刷新旧完整图，刷新率与新照片更新率不同。

`sim/check_camera.py`通过：真实COBS/SLIP编码解析、三张完整上传、忙/NACK重试、丢END ACK不重复发布、只取最新帧、BGR/RGB和尺寸、数据中途立即停止、数据中途请求完整帧后暂停、间隔等待停止、串口/相机释放、相机断开、GUI参数锁定。所有串口和相机用可控mock替代，结果在 `sim/camera/verification.json`。

本机OpenCV4.12.0已可导入，但编号0/DSHOW实测未打开成功；没有真实串口上传或本机照片实屏结果。用户反馈的前一版四风格效果认可照常保留。架构入口：[architecture.html](../architecture.html)。

易灵思V4工程的显示已按用户要求调整为720p30，输入/CNN仍选择VGA；Xilinx保持原720p60时序。两者的串口帧格式与主机采集行为不变。
