# 2026-10-19：六风格彩色边框修复

## 原因和范围

彩色框已存在于六风格软件预测，尤其浮世绘底部粉色条、漫画四周色线明显，因此位于CNN边界处理。原实现每层将图像以外的特征补0。五层膨胀率1/2/4/8/16，累计影响边缘31像素；经过学习偏置、卷积与饱和后，零填充区域会形成不自然色带。它不是额外绘制的装饰框。

对同一组学习参数做受控对照：只替换边界取样，内部距边缘31像素以外逐值不变，六种彩色边框消失或显著减弱。复制边缘虽然能去掉色带，但会产生重复拉长的边缘纹理，本轮采用更自然的逐层镜像延伸。

## 新的确定性边界规则

- 正常轴使用reflect-101：`... c b | a b c ... | b a ...`，边缘像素不重复。例如横坐标-1映射1，W映射W-2。
- 对长度不大于本层dilation的极小轴，回退到该轴的边缘复制，确保1×1等测试尺寸也有定义；真实720p/VGA各轴均使用镜像。
- 在每一层隐藏特征上执行同一规则，不能只给RGB输入加一次边框。
- 原始尺寸、视野、像素顺序及DDR帧布局保持1280×720或640×480。没有裁掉外圈、缩放画面或另绘覆盖条。
- 六组已学习权重、偏置、移位不变，没有在这次边界修复中重新训练。原检查点的训练条件仍为zero；新推理策略由独立模块`pycode/art6_border.py`和签核manifest记录，不能把旧checkpoint直接前向的补零输出说成新版结果。

## 软件与FPGA对应

`art6_border.predict()`在PyTorch逐层镜像后执行原定点卷积；`integer_network()`采用独立NumPy int64实现。旧`hardware_network.py`和`export_hardware.py`及旧训练启动指纹保持不变。新效果图由`pycode/render_border_art6.py`生成，原`results/art6_v2`完整保留。

FPGA在`style_conv3x3.sv`的行缓存读地址上镜像映射。每个镜像样本在读取前已收到，行龄不超过2×dilation，仍在同一个环形行缓存中；无需增加帧缓存或改DDR地址。协议、像素数、握手延迟和MAC/量化逻辑不变。更改地址逻辑后仍需重新综合、布局布线、时序和88脚审查，不能沿用昨天的bit指纹。

## 旧版保留

本项目`build/baseline_zero_border_20261019/`保存97个文件，包括两份旧bit、源码、约束、参数、报告与签核。旧四风格工程、公共RTL和易灵思工程不改。之后如果将这套镜像策略移植到分条处理，只能在全图真实边缘执行，不能把条与条之间的重叠边界误当全图边缘。

## 时序优化过程

首轮镜像的通用32位地址计算在末层tap到行RAM地址出现setup −0.564ns，因此候选拒绝交付。优化为9个tap显式译码、按ROW_BITS限宽计算行龄及环形下标，并把正常尺寸的边界表达式按轴拆开；MAC、RAM读延迟及数据握手保持原样。优化后的所有仿真与两套CAD需重新通过，不给该路径添加多周期或假路径。

最终版同时核对旧97文件、六模型/编译参数未变、两配置相同权重与完整仿真slot0参数，复核PASS；本轮未上板。
