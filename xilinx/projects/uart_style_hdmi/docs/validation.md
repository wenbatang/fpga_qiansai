## 电气、CDC与报告说明

84个实际路由端口匹配原理图：Bank14/15为3.3V，DDR Bank32/33为1.5V，VCCAUX_IO为1.8V/NORMAL，外部VREF；DDR3-800。输入G22为50MHz，系统/IDELAY200MHz，DDR CK400MHz，UI100MHz，像素/串化74.25/371.25MHz。两套配置不改变引脚或电平。

内部未约束端点、无时钟端点、组合环均为0，DRC无Error。CDC报告有12项同步器Info、4项复位同步Info和**2项MIG内部复位链缺ASYNC_REG属性警告**，不是“所有警告为0”。方法学报告仍有MIG/PLL和复位组合逻辑相关LUTAR警告及SERDES复位建议；保持厂商IP和已核对的基础复位拓扑，实板验证应包含复位、PLL失锁/重新锁定和DDR重新校准。

`check_timing`仍提示异步复位/串口输入和DDR复位/TMDS相关外部端口未设置常规同步I/O延时。UART按异步同步器处理，DDR PHY约束由MIG管理，HDMI为转发时钟串化输出。内部时序通过不等于HDMI接收端信号完整性已实测，不能用WNS代替实屏检查。

## 十秒目标与板上验收

2Mbps、8N1、720p RGB565像素下限9.216秒，COBS/ACK预算约9.25–9.28秒；1280×720推理还需约0.15秒及安全消隐等待。USB驱动和软件开销仍可能使总时间超过十秒，必须记录实际完整END ACK，不以线速预算作通过结论。

1. 核对要使用的bit指纹，明确授权下载到FPGA；本次未写SPI Flash。
2. 先用VGA bit和GUI的`vga`配置测实际640×480推理周期；使用720p照片时显式选缩放。HDMI应为居中640×480和黑边。
3. 再用默认bit和`720p`配置，逐一发送四风格720p原图。记录总用时、上传至END ACK用时和FPGA推理周期；确认完整换帧和错误恢复。
4. 超十秒时先分解USB/包等待与纯像素线速开销，核对串口适配器、驱动和实际稳定波特率，再调整，不能把传输截止到最后DATA当作完成转换。
5. 单帧等效fps不是连续视频fps。最终Ti60摄像头30fps输入、>15fps实际新风格帧、原图/风格对比和FPS叠加仍须持续测试。
