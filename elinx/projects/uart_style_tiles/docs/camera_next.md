# SC431HAI确认与最终链路实施入口

用户2026-10-13明确纠正：此前SC432HAI是笔误，实际摄像头为SC431HAI。新资料为[SC431HAI数据手册V1.1](../../../elinxdemo/Ti60F225_DemoBoard_v4/摄像头SC431HAI_数据手册_V1.1.pdf)，2024-08-16版本。已提取并视觉核对Sensor ID/MIPI页面，原资料不改。

## 已确定的启动检查

- 手册第10–13页：16bit寄存器地址、8bit数据；SID低时7bit从地址0x30，SID高时0x32。V4参考I2C控制器默认使用包含R/W位的8bit写地址0x60，不能把0x60直接传给要求7bit地址的软件API。
- 上电/复位后先读取0x3107、0x3108，期望ID=0xCD6B；读回失败或不匹配时不继续加载模式表。身份核实与图像模式核实分开进行。
- 第8页给出释放XSHUTDN到初始配置至少4ms的约束；结合板卡供电与外部时钟核对上电时序。复位、I2C和MIPI物理接口重新做整机引脚/电压审查，不以当前UART工程66端口签核代替摄像头端口检查。
- 第2/13/16页：支持RAW8/RAW10与1/2/4-lane MIPI。选参考例程实际lane数并读取CSI数据类型/word count；核实Bayer排列、镜像与翻转。不要把8bit HS接口拍宽当成RAW8像素位宽。

## 参考例程不能直接当作目标模式

V4本地V7例程的顶层HACT/VACT为1920×1080；其有效I2C表最后写0x3208/0x3209=0x0780、0x320A/0x320B=0x0438，同样对应1920×1080。表中0x0100=1出现在最后一组窗口/曝光寄存器之前。新驱动应明确待机、模式设置、校验和最终stream-on的顺序，不能只看到型号一致就直接认定是1280×720/30fps初始化。

手册描述了窗口与帧率寄存器，但没有给出可直接上板的完整1280×720模式表。厂家模拟/PLL配置沿用对应已验证模式；改变HTS/VTS、窗口或lane时需核对像素时钟与CSI速率，最终FPS以FS/FE计数实测。可先复现原1920×1080模式，再经过确定的RAW→RGB、缩放/裁剪产生目标尺寸。

## 最终目标的实施顺序与验收

1. 先上板验证本项目UART720p完整照片：DDR校准、正确颜色/无拼接缝、四键、ACK总时间、错误恢复与推理周期读回。该阶段不等同实时视频。
2. 复现V4原SC431HAI摄像头模式，读取ID与关键模式寄存器，统计FS/FE、行数、word count、ECC/CRC/FIFO错误，确认真实30fps。
3. 摄像头前端保持持续服务，通过异步FIFO、RAW解包、Bayer→RGB、目标尺寸转换写原图双缓冲。半帧与溢出帧不发布；如果推理落后，采用最新完整帧并记录主动跳帧数。
4. 将分条引擎源地址参数改为受控作业描述，锁住原画帧所有权；并扩展DDR读写仲裁支持采集、推理和显示三个客户端。推荐三个原画bank（正在采集、最新完整、推理锁住）加两个风格bank，避免只用两个原画bank时推理完成却必须等待正在采集的半帧。释放仍被读取的bank前不得覆盖，丢弃旧待处理完整帧需计数。
5. 加入本地Sapphire/RISC-V基线，通过CSR控制I2C、源/目标地址、尺寸、权重加载、启动、完成/错误中断、计数。四个ROM槽的按键选择目前已实现；运行时权重加载目前尚未实现，必须单独验证加载长度/校验与busy写保护。
6. 在HDMI叠加“采集FPS、推理新帧FPS”，刷新30Hz独立标注。原画/风格对比必须来自同一源帧。按用户要求本阶段720p30，原赛题720p60/1080p30条款仍保留为资料验收来源。
7. 以640×480稳定>15fps完成基础推理指标与持续运行验收，再优化720p实时性能。CAD资源/时序、仿真周期、UART预算与真实板FPS分别报告。

当前没有把MIPI、RISC-V或动态权重集成进分条bitstream；没有下载板卡。新增摄像头端口或IP之后必须重新综合、布线、时序、所有引脚签核，不能复用当前bitstream结论。
