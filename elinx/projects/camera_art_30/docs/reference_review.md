# 47 风格工程的收益与四风格 30fps 方案

本次只读审阅 `style_model/` 与 `style_model/elinx/`，实现写入独立的 `elinx/projects/camera_art_30/`。原47风格、原 RF33 模型、原已签核 bit 均保留。用户反馈的约20帧为实际使用反馈；磁盘中的47风格签核明确标记未上板，其完整720p CNN/DMA模型为4,065,356个100MHz UI周期，约24.60fps，两者测量范围不同。

## 参考设计做得好的地方

1. **把算力用于风格残差。** 原始720p RGB旁路保留细节；2×2池化后的640×360分支预测RGB变化，再最近邻放大回加。与直接缩小输出画面不同，最终输出仍完整720p，但不是每层卷积都在720p上执行。
2. **深度卷积加逐点卷积。** C8 stem3×3后接4组DW3×3/PW1×1，膨胀率1/2/4/8。每原图像素约196MAC，而此前6通道RF33密集卷积为1296MAC。DW负责空间纹理，PW负责通道混合，隐藏层残差和RGB旁路保留内容。
3. **47风格共享计算数据通路。** 风格切换加载一套参数，不是同时实例化47个CNN。四层DW和RGB输出head在47组导出中完全相同，可固化为共享常量，stem/PW保留RISC-V运行时配置。共有346个兼容配置事务；并不是346个都改变计算常量。
4. **有明确的数值合同。** uint8激活、int8权重、24bit有符号累加、25bit舍入、每输出通道二次幂移位、饱和。所选参数的保守累加界小于2^23；不代表任意新权重都安全。冻结BN折叠是推理近似，不能称为实时IN。
5. **保留全图语义。** 条带左右32像素重叠、全局偶数池化相位、真实边界reflect101，人工条带边界不冒充图像边界。帧发布等所有条带与最终DDR B，不能逐条上屏。

## 仍可改进的地方

旧 `tiny_pointwise.sv` 发射8个输出通道后，等待6级算术流水排空及输出握手，理想输入间隔约16个CNN周期。新实现保留两套输入、skip、inside、结果上下文，流水标签携带上下文和通道；已发射像素排空时可计算下一像素。真实四组参数的hidden稳定间隔8周期，输出阻塞时结果保存在各自上下文，禁止提前重用。

首次完整720p优化测试仍需3,713,814个UI周期，约26.93fps，说明局部II改善不能直接当成整机倍速。输出DMA的单个128bit打包寄存器在等待前次DDR B时无法收下一组8像素，是下一处优化目标。采用打包和发送分离的双缓冲，不能删除最后B响应屏障，也不能把AW/W接受当作写入完成。

参考工程两输出bank在完成后等待60Hz消隐，40.65ms计算再等待下一消隐，可能接近50ms/帧。新项目复用已有三bank所有权实现：计算目标与待提交目标分离；第三bank位于10MiB；reader完成旧R排空、FIFO重置及安全窗口后才确认提交。计算完成IRQ可提前释放计算资源，显示前台只有最终ACK后才释放。模型低于33.33ms只是争取30fps的必要条件，还需摄像头供帧、总线并发与控制开销共同验收。

47组参数各按1216B对齐，共57152B；选四组变为4864B，减少52288B。风格数量主要影响存储和切换加载，不直接增加固定单帧计算量。新候选初次综合174/256RAM10、100/160DSP，最终以同次布局布线签核为准。

## 验收口径

- 小尺寸四模型逐像素参考、随机气泡/长背压/在途复位、第三bank与错误恢复分别验证。
- 完整1280×720 CNN/DMA使用真实异步FIFO和有界AXI模型，报告实际UI周期；必须标注与真实DDR/HDMI/摄像头并发的差别。
- Efinity原语映射后的学习参数数值验证不可省略；RTL正确不等于动态context索引映射正确。
- 保持79个板级端口、12组Bank电压、PLL/DDR参数，重查CDC和原生setup/hold；不使用整组异步时钟切断或无依据多周期。
- 最终板上观察C/I/H各自计数和CAM4错误字段，以同风格连续新源帧的I稳定30验收。RAW复制、重复显示和HDMI60Hz不算推理30fps。本轮未下载，不能提前宣称实板30。
