# 四风格30fps候选：模型来源、数值合同与画质对照

日期：2026-10-29。本文件针对新建的 `camera_art_30` 独立实验。只读借鉴 `style_model/` 的已训练C8模型和原 `camera_art_styles` 的RF33基线，未覆盖参考项目、模型、参数或可用bit。当前四风格为梵高、剪纸、漫画、水墨。

本阶段的关键选择是：**先复用47风格工程中已有的四个C8槽位，优化硬件吞吐；保留已认可RF33作为画质基线。** 这沿用四个风格名称，不代表沿用RF33的同一组函数或逐像素效果。C8的训练目标和网络均与RF33不同，如需接近旧画面，应另建蒸馏实验后再比较。

## 1. 47风格工程中值得借鉴的地方

1. **降低空间计算尺寸，同时保留全尺寸原图。** 输入1280×720，计算支路先2×2均值池化到640×360；最终只把学习得到的RGB残差放大、加回原RGB。卷积作用于四分之一像素，原图旁路保留较细的线条和文字。[网络实现](../../../../style_model/network.py)第50–63行。
2. **将dense卷积分解为DW/PW。** DW3×3分别处理各通道空间纹理，PW1×1混合通道；单风格784个卷积系数、196 MAC/原图输出像素。八通道不是比六通道“更轻”的充分理由，真正收益来自算子分解和半尺寸计算。[网络层定义](../../../../style_model/network.py)第35–40行。
3. **隐藏层和RGB两级残差。** 四个DW/PW块均带残差，末端再加原RGB，减少必须由小网络从零重建内容的压力。代价是高频风格变化受半尺寸支路限制，不能保证等同于完整分辨率风格网络。
4. **训练时折叠实际部署图。** 风格仿射、固定BN、逐输出通道二进制移位均进入最终导出和校准；推理不计算每帧IN统计。[部署QAT](../../../../style_model/network_deploy.py)第7–38行、[整数导出](../../../../style_model/integer.py)第9–47行。
5. **共享与风格相关参数分开。** 当前47套导出中四个DW和head的权重/偏置/移位逐字节相同，因此参考RTL将它们固化，CPU只需真实更新stem和PW的风格相关部分。这是针对已冻结这批模型的事实，不是可任意换模型的通用假设。[共享常量生成与断言](../../../../style_model/elinx/scripts/shared.py)第9–21行。

参考工程 `style_model/elinx/README.md` 记录完整720p梵高CNN/DMA模型为4065356个100MHz UI周期，约24.60fps；这个模型包含真实异步FIFO和有界合成AXI，**不含完整物理DDR、摄像头和HDMI并发**。用户本轮报告约20fps是用户观察，不能把两种范围互换。30fps必须通过新工程的完整帧测试和最终板上计数确认。

## 3. RF33与C8的计算及画质合同

| 项目 | 已认可RF33 | 新候选C8 |
| --- | --- | --- |
| 输入/最终输出 | 1280×720 RGB565 | 同样1280×720 RGB565 |
| 内部空间尺寸 | 全1280×720 | 池化后640×360 |
| 主干 | 5层dense3×3，3→6→6→6→6→3 | stem3×3 3→8；4组DW3×3/PW1×1；head1×1 8→3 |
| 膨胀率 | 1/1/2/4/8 | stem1；四DW为1/2/4/8 |
| 跳接 | 无原RGB旁路 | 四个隐层残差和最终原RGB旁路 |
| 单输出像素卷积MAC | 三彩色模型1296；水墨软件单输出为1188，既有硬件扩三路仍按1296 | 196，均值池化/残差/寻址另计 |
| 720p单帧卷积MAC | 彩色模型1.1943936G | 0.1806336G |
| 720p30必要卷积吞吐 | 35.831808 GMAC/s | 5.419008 GMAC/s |
| 理论感受野 | 原图33×33 | 低尺寸支路33×33，对原图依赖66×66 |
| 模型归一化 | 冻结BN折叠 | 冻结BN和风格仿射折叠 |
| 输出 | 每层饱和0..255，最后直接RGB | head为有符号RGB残差；与原RGB相加后饱和 |
| 水墨颜色 | 单通道结果复制到RGB，再RGB565量化 | 三路RGB残差加原RGB，可能有轻微底色 |

上述MAC只计每个有效卷积像素，不含条带halo、流水气泡、DDR事务或换帧等待，不能由此直接宣称6.61倍实板速度。C8计算支路的66像素依赖来自2像素池化窗口和半尺寸RF33。对于偶数对齐池化及条带中心区，左右各32原图列可覆盖相邻中心块所需上下文；不能把66×66感受野误写为无需halo。

当前C8残差在每个2×2输出块中相同，叠加的原RGB仍逐像素不同。因此原画细节可能更清楚，但学习到的细纹理受半尺寸计算限制；最近邻残差不是生成了新的高分辨率风格细节。大轮廓、颜色和纹理密度均需实际观看，不能用参数量或PSNR排名代替艺术判断。

## 4. 必须保持一致的定点细节

### 4.1 C8

- 输入RGB uint8来自RGB565位复制扩展；软件图像为HWC/RGB，Torch为NCHW。硬件逐像素总线低8位R、中8位G、高8位B。DDR RGB565小端顺序由顶层保持。
- 池化为2×2整数均值，`(sum+n//2)//n`；奇数边界按实际1/2/4个样本及ceil尺寸。生产720p为偶数尺寸，条带原点和中心列数须保持偶数，不能让条带改变全局池化相位。
- 权重为有符号int8，导出偏置int32；隐藏值uint8，表示6/255刻度。固定BN与风格仿射先折进卷积。
- **每个输出通道独立移位**。舍入为 `floor((acc+2^(shift-1))/2^shift)`，shift=0不加舍入项，负数同样使用这个规则；不能替换为向零截断或对称远离零舍入。
- DW/PW激活先饱和0..255。隐藏残差为 `clamp(h + clamp(PW(DW(h)),0,255),0,255)`，不是把残差改为signed后相加；顺序不同会改变画面。
- head在1/255刻度产生−510..510有符号残差，最近邻放大到原尺寸、裁掉奇数额外边，再与原RGB相加并饱和0..255。最终存DDR前重新量化RGB565。
- 每个空间层采用reflect101；轴长≤膨胀率时退化edge复制。人工条带外部不是另一幅完整图，必须按全局坐标、有效区域和逐层halo处理。
- 原参考47套的保守绝对和上界2196082，小于2²³，所以参考硬件24位有符号累加/25位舍入适用这批冻结模型。这个结论不授权任意新参数缩到24位。

### 4.2 RF33

RF33为每层一个移位、int32偏置和累加、逐层uint8饱和。空间反射合同相同，但没有池化或RGB旁路。水墨最后一层只有一个输出，软件复制RGB；既有FPGA为三输出复制参数。数值比较必须保持同一输入RGB565和最终输出RGB565，不能拿一边原RGB888与另一边RGB565作视觉归因。

两张正常图复用原RF33完整720p图片，同时用导出参数重新计算，**8张缓存均逐像素误差0**。低亮图两边都真实推理。共24张1280×720风格结果，双方均输出RGB565。另用各模型的1×1、9×5、22×19三种尺寸对现有独立NumPy参考测试：4风格×2网络×3尺寸=24个数值用例，最大误差0，覆盖短轴、奇数池化、反射、残差、移位及饱和；这不是24张完整720p都跑了NumPy参考，也不是RTL/网表数值验收。

已观看三个预览，具体差异为：

- 梵高：C8深蓝/黄色更突出、原图细线更多；RF33更平滑，整体蓝灰。两者风格方向相近，但配色和纹理密度不同。
- 剪纸：差异最大。第一张RF33的RGB均值约125/102/87，C8约163/176/122，明显从棕粉改为黄绿且纹理更密。不能宣称无损保留原剪纸效果。
- 漫画：C8的深色轮廓和颗粒纹理更密，可能更有装饰感，也可能遮挡小物体、增加视频闪烁风险；静态两图不能证明时间稳定性。
- 水墨：C8较锐，保留部分细线，但有轻微蓝绿/灰色底；RF33本身更接近单通道。没有把额外灰度后处理偷偷加进候选。

这些是有限样本观察，不是47风格整体排名，也不是用户已接受C8画质。RF33与C8之间的PSNR仅说明两个模型输出不相同，不能直接评判哪一个更像艺术。

## 6. 暗场色块与后续画质选择

软件压暗至25%后，两个网络都会更依赖所学色调：梵高偏蓝、剪纸偏固定色块、漫画偏绿黄、水墨偏灰白。输入暗处细节减少后，模型偏置、饱和激活和所学调色会占更大比重。第一张暗图中C8梵高均值约12/35/81，剪纸约116/156/92；这解释了模型可以形成强色倾向，但不能由此诊断实物摄像头的所有偏色。

原画偏绿涉及Bayer顺序、ISP白平衡、照明及传感器输出；更换CNN不等于修复相机颜色。此前的运行时偏置映射错误已另有实际网表证据和修复，不能因为暗场再次出现色块就直接认定只有光线问题。新参数存储/位宽改动仍需独立整数、真实映射网表和最终整机验证。

如用户要求更贴近已认可RF33，建议在新run中以四组RF33实际输出为教师，对C8做四风格微调/蒸馏，再加入弱VGG风格、边缘、颜色和低光增强约束。最保守先固定四个DW与head，只训练stem/PW风格仿射，这保持现有共享常量；但容量可能不足。若要更新DW/head，也需一起更新硬件常量、位宽证明、所有四模型数值回归并完整重建，不能只替换参数ROM。本轮尚未启动这类训练。

## 7. 复现与交付边界

从本项目 `build/` 运行：

```powershell
& 'E:/software/anaconda/envs/yolo/python.exe' -B ../scripts/quality_compare.py
# 已有预览不默认覆盖；明确仅重建本地预览时使用：
& 'E:/software/anaconda/envs/yolo/python.exe' -B ../scripts/quality_compare.py --overwrite
```

需要本地两组冻结导出和COCO图片，依赖NumPy/Pillow/PyTorch，默认有CUDA时使用GPU，也可 `--device cpu`。输出路径限制在新项目 `build/`。脚本不会改变参考模型，也不把GPU推理时间换算成FPGA帧率。

真正30fps交付还需要新RTL在有界AXI下完整720p数值/吞吐验证、真实映射网表回归、整机资源和原生STA/精确CDC/79脚电气签核、摄像头/推理/HDMI并发上板测量。显示H60、采集C30和真实完成I30分别报告；原画复制与重复刷新不计入推理。模型与新bit的接受范围最终以新项目README、签核记录和实际实屏结果为准。
