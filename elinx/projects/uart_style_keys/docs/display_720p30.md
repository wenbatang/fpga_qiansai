# 处理尺寸与显示尺寸：本轮720p30

用户2026-10-13指定易灵思显示改为720p30。本轮保持输入/CNN640×480，仅调整Ti60显示时序，四种权重、串口格式、DDR时钟和引脚电平不变；Xilinx继续使用原配置。

## 为什么有两个尺寸

处理尺寸是模型每次计算的真实像素网格，640×480共307,200个像素，RGB565原图614,400字节。显示尺寸是HDMI有效画布，1280×720共921,600个像素，决定屏幕接收的视频格式。

当前RTL没有缩放器：处理后的640×480图像逐像素居中显示，左右各320像素、上下各120像素填黑。CNN和DDR只保存/读取640×480图像，黑边由视频时序模块直接生成，不必在DDR存一幅720p黑边图。

选择VGA是为了控制Ti60资源与计算量。720p的像素数是VGA的三倍，串口字节数也是三倍；CNN行缓存还随图像宽度增大。旧完整VGA构建已经使用240/256 RAM10、144/160 DSP。把显示改成30Hz不会缩小CNN行缓存，也不会自动增加图像细节。若以后要铺满屏幕，可以在显示端按比例放大；放大仍不等同1280×720神经网络推理。

## 本轮显示时序

采用CTA VIC62的1280×720@30Hz、正HS/VS时序。依据Linux内核的[CTA模式表](https://code.googlesource.com/linux/torvalds/linux/+/0bdf0621f89f87858ca26344378188eff194eddd/drivers/gpu/drm/drm_edid.c)，标准30Hz使用74.25MHz像素时钟、3300×750总周期。

| 参数 | 数值 |
|---|---|
| 水平有效 / 前肩 / 同步 / 后肩 | 1280 / 1760 / 40 / 220 |
| 垂直有效 / 前肩 / 同步 / 后肩 | 720 / 5 / 5 / 20 |
| 水平 / 垂直总周期 | 3300 / 750 |
| 像素 / 半速LVDS时钟 | 74.25 / 371.25MHz |
| 刷新率 | 74,250,000 ÷ (3300×750) = 30Hz |

保持USER_PLL的VCO2.970GHz与40/8输出分频，实例化`video_720p`时显式设置`H_FRONT=1760`。公共视频模块仍保留720p60默认参数，避免影响Xilinx。长水平消隐期间持续发送规范TMDS控制码，完整帧发布依旧只能在安全垂直消隐窗口完成。

显示30Hz指每秒刷新30次已完成的图像。UART上传FPS、CNN处理FPS和显示刷新率分开记录：2Mbps下VGA裸像素就需3.072秒，尚未计协议、推理和换帧，因此串口相机路线不会每秒更新30张新照片。显示控制器不发送AVI InfoFrame/不读取EDID；实际屏幕对该时序的接受情况仍需上板检查。

## 验证与回退

`sim/check_video.py`检查连续三幅3300×750完整时序：921,600个有效显示像素、居中307,200次图像读取、黑边、正同步宽度、消隐换帧窗口、一次下溢计数及下一帧恢复。仿真中的时钟仅加速执行，实际刷新率由签核PLL参数与总周期计算。

新模型/RTL/配置/时序/引脚/bitstream指纹在`build/vga/signoff.json`。原720p60构建、当时源码与说明完整保存在`build/baseline_720p60_20261013/`，文件校验清单为`archive_manifest.json`。生成新的配置文件不等于实屏验证；本轮不下载板卡。

原赛题资料列出的720p60或1080p30指标仍在根目录验收记录中保留。当前720p30是用户指定的阶段显示配置，不据此宣称原赛题全部验收完成。
