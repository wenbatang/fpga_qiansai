# 共享单拍写通道的事务压力测量

本轮对生产模块 `rtl/axi_write_pair.sv` 做了独立仿真，没有修改生产RTL、DDR IP、约束、模型或bit，也没有运行CAD/访问板卡。

结论：当前单拍、单在途写结构对**响应延迟**非常敏感。在本次合成服务模型中，附加B响应延迟13个UI周期仍能跟上目标平均需求，14个周期已持续积压，15/16/24个周期发生有限队列溢出。这个边界不是实物DDR控制器的测量，不能直接写成“真实DDR只允许13拍”。

## 1. 测了哪些部分

- DUT是实际 `axi_write_pair`：两生产者轮询选择，一个事务从选主保持到B，AW与W可分别接受。
- 两个合成生产者均遵守AW/W/B停等；地址/数据在背压时保持，直到B才完成本词。
- 等待FIFO容量分别为采集512个128-bit词、CNN128个词；生产者另有一个正在发送/等B的寄存词。因此表中的最大“等待＋在途”可以为513/129。
- 采集按真正1280×720、RGB565、30fps平均产生需求：每帧115200词，每秒3456000词，即0.03456词/UI拍。
- CNN按完整RF33候选测试的6007407个100MHz UI周期/帧产生需求：115200/6007407≈0.0191763词/UI拍，对应约16.646fps。
- 到达使用整数相位累加器，避免将小数平均率取整成错误的固定周期；本测试是均匀平均需求，没有模拟真实摄像头行突发或CNN突发。
- 合成DDR从机每7拍独立阻塞AW一拍、每5拍独立阻塞W一拍；同一时刻只有一个写事务在途，没有读流量或厂商DDR模型。
- 每个延迟点持续到达400000个100MHz UI周期，随后停止新需求、继续50000拍排空。九个点分别为0/4/8/12/13/14/15/16/24。

总目标平均需求约为 **85.978MB/s**，必须平均每 **18.6094个UI周期**完成一个128-bit词。该值比“推理仅15fps”的每19.29拍更紧。

## 2. B_DELAY的精确定义

AW、W分别握手后，从机记录两个通道均已收到；最早下一拍将BVALID寄存为1。`B_DELAY=N`表示在这个最早注册响应之外再等待N拍。

当AW/W错拍接受时，首个通道至B握手还包括等待另一通道的时间。此测试各点观测到“首个AW或W接受→B握手”的最大延迟为N+3拍。表中的N不是事务从选择到释放的总周期，也不是厂商文档里的DDR CAS等参数。

延迟14拍时，采集积压在后半测量窗口再增加26词，最终55词。虽然4ms测试尚未耗尽512词等待FIFO，仍明确标记为`FAIL_BACKLOG_GROWING`，没有因为“尚未溢出”就认定持续可用。

协议本身没有错主、地址/数据背压变化、丢响应或未记账数据。所有点排空后都满足：

```text
成功完成词 + 队列丢弃需求词 = 持续到达的总需求词
总线B事务数 = 两生产者成功完成词之和
```

结果JSON整体标记为`MEASURED`，`protocol_result=PASS`只表示协议检查通过。每个延迟点单独保留`SUSTAINED_IN_MODEL`、`FAIL_BACKLOG_GROWING`或`FAIL_OVERFLOW`；慢延迟没有被包装成容量PASS。

CNN合成生产者在这里是开放环目标需求，队列满后计数的是“目标率无法被服务的词”。真实CNN有背压能力，通常会停住并降低推理FPS，而不是允许丢像素后发布图像；真实摄像头不可背压，溢出则应使该帧失效。该测试没有把上述丢弃词解释为板上已经丢失的帧或像素。

## 4. 对下一步实现的影响

1. 当前三输出bank只能去掉显示提交等待，不能消除共享写通道的停等代价。内核16.646fps留给真实并发的余量有限。
2. 首先测真实整机的采集FIFO水位/溢出、AW/W等待、等待B周期、读仲裁及完整帧计数。单看85.978MB/s远低于1.6GB/s物理/UI峰值，会漏掉每词一次响应造成的事务瓶颈。
3. 若实物最坏延迟或读写竞争接近本模型的积压区，应优先评估连续16拍写合并。相同数据量下，采集＋16.646fps推理的写响应事务理论数量可从约537万次/秒降至约33.6万次/秒，减少16倍；数据拍本身和读写争用仍然存在。
4. 写合并必须整体调整生产者、仲裁、AWLEN/WLAST及实际DDR IP兼容性，遵守4KiB边界；不能只把顶层AWLEN从0改成15。帧发布仍等全部突发的最终B，发生任何写错整帧作废。
5. 本测试没有显示读、CNN原画读、刷新、行切换、MIPI突发、CPU或真实DDR。模型内延迟13拍通过只是一个控制条件下的观测边界，不能代替实板、完整SoC并发或时序签核。

## 6. 小范围改进：两主各保留一个真实在途事务

新增独立 `rtl/fps/axi_write_pair_fps.sv`，端口与旧 `axi_write_pair` 完全相同，没有修改旧模块：

- 每主最多一个在途，合计最多两个。grant时预留owner FIFO和该主credit，只有真正的B握手才释放credit。
- 一个AW/W对的两个通道都接受后，可以发另一主的下一对，不再锁整个B等待时间。AW先、W先、分别背压均允许；配对顺序不能交叉。
- 两项owner队列按grant顺序记录。只有对应AW/W均完成的队首才可路由真实B，不产生提前或合成响应。
- 所有请求仍为单拍、同ID0；从机须按请求顺序返回B。原始BRESP，包括SLVERR/DECERR，直接路由给对应主。
- 上游原writer仍在自己的真实B后才继续，最终帧B屏障没有提前。

该模块仅使用少量寄存器，未增加图像RAM或改变AWLEN/WLAST。但完整实现仍需要新整机综合、时序和真实DDR并发确认。

### 独立协议测试

主测试包含30,000周期持续压力/随机背压和50,000周期排空，完成2328个真实B事务，包括743个按词身份核对的错误响应、1689拍B背压、546次AW先/595次W先、57次从机响应队列同拍push/pop、65次仲裁owner队列同拍grant/retire、最多两个真实在途。另有AW已接收但W未接收时复位，以及两个owner均在等待B时复位的定向场景。

逐拍检查包括：无提前B、无错主/双主B、同主不能在真实B之前再发下一AW/W、AW/W各自背压保持、配对身份一致、B背压稳定，以及最后排空后的逐词记账。0 Error、0 Warning。主回执 `sim/fps_write_pressure2/verification.json`，`unit.json`为同内容别名。

为确定16与24之间的边界，又独立扫描16/17/18/19/20/21/22/23/24九点，每点同样400000拍。新仲裁器在16–23拍均无丢弃、无持续积压，采集最大积压1–2词；24拍仍复现492词峰值及后半窗口+245词。回执 `sim/fps_write_pressure2/boundary/results.json`。因此本控制模型中观测到的附加B延迟上限由旧13拍扩至新23拍，不能外推为真实DDR的保证。

两项从机模型能提前接受第二主的AW/W，同时等待第一主B。真实DDR若不接受第二项，AWREADY/WREADY会继续背压，新仲裁器保持正确握手，但不能据该模型宣称已获得相同提速。测试仍不包含显示读、推理读、真实DDR刷新或真实图像到达突发。
