# 原画对照、放大与暗场诊断

> 后续CAM3及综合网表已定位CNN偏置通道错位，当前使用[偏置修复版](bias_mapping_fix.md)。本页保留camera_view60诊断版当时的验证与操作记录。

2026-10-23，独立候选 `build/camera_view60/`，继承已签核 SoT 恢复版。用户已实测旧恢复版 **C30 / I02 / H60** 并有图像，但暗场大面积纯色或黑，亮场仅少量细节。这确认了能采集、完成处理、输出画面，尚不能确认 Bayer、曝光、颜色、输出像素和显示欠载均正常。

## 本版改动

- 处理保持 **640×480**。显示用3:2最近邻放大为 **960×720**，在1280×720中左右各留160列黑边，保持4:3，不变形。标准720p60、74.25MHz、1650×750、VIC4、串化与P/N补偿不改。放大便于观察，不会生成更多原图细节。
- 启动后先显示**原画**，经过相同DDR输出bank和安全换帧；单按 KEY0/1/2/3 分别进入梵高厚涂、彩色剪纸、复古漫画、水墨。按住 **KEY1＋KEY2约0.5秒**回原画；KEY0＋KEY3一秒逻辑复位保持。长按预览组合时，按下初期可能先出现一次单键风格请求，随后以原画请求为准。
- 原画选择在**整帧作业启动时锁存**，忙时更改不会把一个输出拼成部分原画、部分风格。切换需等当前完整作业及下一作业完成，CNN每帧约0.47秒，不能要求按下后立即响应。
- 原画复制仍通过source claim/lock、三原画bank、同一AXI读写DMA、双输出bank、最后DDR B响应、消隐commit，避免直接显示仍被摄像头写入的bank。原画复制不计入I；I00在原画模式是正常现象。
- 显示缺数据由旧版的亮粉色改为明确的**红黄棋盘**，持续到本刷新帧结束，下个刷新重新尝试。这是错误提示，不是画风。绿色/粉色本身不能证明欠载；旧版只有精确的FF00FF标记具有这一来源。
- 追加最近完整预处理帧和最近成功输出作业的RGB均值统计，经 `@CAM3` 只读串口输出；不增加摄像头命令、不改变传感器增益/曝光表、不改变四组模型。先拿原画证据，避免把错误归因于训练。

本版不是亮度/白平衡或画质根因已经修复。当前预处理仅RAW10降至8位、2×2 Bayer和裁剪，没有完整ISP、自动曝光/白平衡或gamma。原画若偏暗/偏色，应先定位输入；原画正常但CNN异常，再查真实权重/输入分布和网络量化。Bayer仍按BGGR初始配置，必须用真实色卡验证。

## 工作流和时钟

1. 25MHz域启动保护等待PLL；100MHz UI域DDR校准后释放CPU/相机控制。摄像头模组RESET、开漏I²C、ID CD6B、V7待机表、尺寸/VTS/曝光读回与权重加载，保持原25032字节固件。
2. SC431HAI输出1920×1080四lane RAW10；D-PHY公开PPI44记录通过原子异步FIFO进UI域，校验CSI/ECC/CRC/尺寸/EOF。保留上版严格限定的空闲SoT告警恢复及所有硬错误判据。
3. Bayer合成960×540后裁剪640×480，标准RGB565，高5位R、中6位G、低5位B。统计每个已生成的完整有效帧，两像素/拍，无反馈到采集。DDR中每128位拍8像素，早像素在低16位。
4. CPU启动作业，先claim锁住最新完整源bank。原画模式按原像素复制；CNN模式运行原十二通道五层模型。CNN内部RGB按低字节R打包，出引擎还原标准RGB565；不是HDMI的24位RGB位序。
5. 全部20条中央32列写完、最后DDR B响应后，作业才成功，RGB输出统计才更新。显示reader在安全消隐提交完整输出，未完成或失败帧不得提交。
6. 74.25MHz像素域的640×16同步行缓存做3:2放大。每3个输出列取源0/0/1，每3个输出行取源0/0/1；第二行重读缓存，另两行各读一条源行。每刷新仍只读307200个源像素，缓存占2 RAM10。RGB/DE/HS/VS/坐标统一增加一级延迟。

新模块没有新增跨域多位payload。计数与RGB统计均为UI域；UART原子快照也在UI域。旧refresh/Gray/FPS握手保留，不能把UI统计总线直接送像素域。

## 上板操作

仅在本目录 `signoff.json` 与 `final_review.json` 均PASS后，将同目录 `outflow/ti60_camera.bit` 用Programmer的JTAG模式临时下载。板卡仍为Ti60F225I3 V4，沿用已确认J4及J2/J3均2–3；本轮不写Flash，不另烧固件，不上传图片。模组不要带电插拔，J8不是UART。

1. 初始先看放大的原画。用明亮场景、白纸、红绿蓝物体检查轮廓、亮度和色相。
2. 再分别单按四键，对比相同场景；按KEY1＋KEY2回原画。记录哪些风格异常、原画是否也异常。忙时等待至少一个完整作业。
3. 若出现红黄棋盘，记录其起点、覆盖区域和是否反复；此时优先查显示DDR读服务/欠载，不先调模型。
4. 板载USB串口115200/8N1，可用串口助手复制完整`@CAM3`，或运行下列只读工具。

```powershell
python F:/fpga_qiansai/elinx/projects/camera_art_styles/pc/camera_view.py --list
python F:/fpga_qiansai/elinx/projects/camera_art_styles/pc/camera_view.py --port COM31 --log F:/fpga_qiansai/elinx/projects/camera_art_styles/build/camera_view.jsonl
```

COM31为示例，以实际端口为准。先关闭占用同端口的串口助手/上传GUI；工具不发送数据，打开前设置DTR/RTS=False，Ctrl+C停止。驱动打开瞬态不由脚本保证。旧CAM1/CAM2工具不能解析新33字段记录。

## CAM3字段

每秒原子快照一次：前24项与CAM2同序；之后9项为 `source_pixels, source_r_sum, source_g_sum, source_b_sum, output_pixels, output_r_sum, output_g_sum, output_b_sum, view_mode`，全部HEX32。总304字节，包括`@CAM3,`、逗号、CRLF。

RGB均值=`sum/pixels`，范围0..255，统计的是RGB565展开后的8位值。源统计为最近完整预处理帧，输出统计为最近成功作业，**未关联同一帧号**；不能将均值差当网络像素误差，也不能证明DDR中数据与观测源逐像素一致。

`view_mode` bit0请求原画、bit1引擎锁存原画、bit3:2已加载风格、bit5:4请求风格、bit6已提交原画；其他位0。尚无成功输出时的默认bit6不表示已有前台图像，仍须看CAM状态FRONT。原画RGB均值接近0是暗输入的证据；正常源均值而输出近0则支持继续查CNN/权重/量化。均值不能代替图像与色卡判断。

## 验证和边界

- 放大扫描：4个完整720p帧、4950000周期，独立坐标oracle验证每个输出像素；正常帧691200个放大像素和307200次源读；缓存重复行FIFO空不误报，真实缺数红黄棋盘，下帧恢复。
- 联合实际frame_reader、真实厂商FIFO RTL与放大扫描：两帧1382400个图像像素、614400次源读、4800突发，逐值一致；有效区排队的bank请求在下一安全消隐提交；有界AXI模型下零欠载/读错误。不是实物DDR/CNN并发带宽保证。
- 新真实CNN/DMA：四模型128×24整数输出逐像素误差0；原画复制逐值一致；跨条带模式锁存、最终B、背压、RRESP/早RLAST/BRESP错误及下次恢复通过；输出RGB统计逐值对照。不是完整SoC或摄像头画质验证。
- 按键、合法/短帧/坏帧统计、实际系统神经网络独立计数、CAM3真实115200逐位解码/中途复位、305种分片解析、新实际顶层开漏/ACK/失锁/停钟/校准失效保护分别通过，黑盒与模型范围按回执记录。
