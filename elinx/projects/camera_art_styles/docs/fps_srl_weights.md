# 六通道RF33权重SRL替换与数值验证

日期：2026-10-24。此文件记录新SRL模块的独立验证；整机布局布线、时序、电气和可下载文件状态以项目README、architecture.html和对应signoff为准。

## 改动范围

新增三个独立源文件，原FF版C6、原12通道、所有模型和历史工程保持：

- `rtl/fps/fps_srl_weights.sv`：顺序加载的浅权重存储。
- `rtl/fps/fps_conv3x3_srl.sv`：从原C6卷积复制，仅更换模块名和权重存储连接；乘法、累加、定点舍入/饱和、流水、固定通道偏置写入和边界计算保持。
- `rtl/fps/fps_cnn5_srl.sv`：五层连线与原C6一致，只连接上述新卷积模块。

继续使用原 `fps_line_ram.sv`，五层通道为3→6→6→6→6→3，膨胀率1/1/2/4/8，隐藏输出通道并行6、末层并行3。四种风格仍为梵高、剪纸、漫画、水墨；现有真实学习参数不变。

权重仍由RISC-V完整写入365项32-bit配置，原地址/数据顺序、APB严格expected_address校验和最后cfg ACK/提交保护不改。

## 为什么需要SRL

首/末层每tap有144bit权重，三个隐藏层各288bit，每层只有九个tap字。全部浅表用FF存储共需10368个权重位，还需要宽九选一读选择器；整机即使RAM/DSP预算满足，也可能因XLR/FF/LUT超限装不下。

每层将前八个字组成一个移位银行：每个数据位用无复位8-bit移位寄存器；第九个字用一个普通FF。完整升序写八次后，按`shift_reg[7-read_word]`读回原地址；单字末银行直接读取该FF。保留原来的`weight_word`读寄存器，因此不改变tap/样本/偏置/valid之间的时钟对齐。

五层合计实际权重存储为1152个SRL8和1152个末字FF，保存同样10368bit数值。**这是完整顺序加载接口，不是任意地址随机更新RAM。** CPU必须完成整组365项后才可提交；当前APB逐项地址校验保证该前提。内核/条带复位不清权重，系统复位后的weights_valid保护及完整重载保持。

## 真实小core映射结果

使用Efinity2026.1.132、Ti60F225/I3、4线程，对24×40真实RF33 core做map；两版尺寸、通道和数值完全相同：

| 资源 | 原FF权重core | 新SRL权重core | 差值 |
| --- | ---: | ---: | ---: |
| RAM10 | 14 | 14 | 0 |
| DSP | 126 | 126 | 0 |
| FF | 26766 | 17550 | −9216 |
| LUT4 | 14934 | 9168 | −5766 |
| SRL8 | 原有流水 | 1172 | 其中1152个经网表路径确认属于权重 |

当前map还报告6522个ADD。FF、LUT、ADD可以在XLR内配对，不能直接将这些原语相加称为布局后的XLR占用。这里只证明实际推断出SRL且减少了逻辑原语，不把小core map称为新整机容量或时序签核。

映射证据：`build/fps_c6_srl_mapped/mapping.json`、同目录outflow的map.rpt/map.v。新整机需独立构建，不覆盖失败的FF候选报告。

### 两条160→144位告警

首/末层每tap有18个int8权重，即144个有效位；365项协议将每字拆成五个32-bit chunk，共160位。最高16位为padding，原FF赋值也仅保留低144位。

新SRL的`write_data`端口明确为144bit，而组合表达式仍为160bit，因此Questa产生两条连接宽度告警并按Verilog规则舍弃最高16位。这是预期padding截断，非有效权重丢失；已经由四模型RTL和真实映射整数回归确认。为保持并行完整720p测试和构建源指纹，本轮不为消除这两条告警改写冻结源。

## 复现

`sim/fps_srl/check_core.py`按`--export`与`--name`执行一个模型的RTL整数检查，`sim/fps_srl/collect.py`校验并汇总四次已完成运行。

`scripts/fps/check_srl_mapped.py map`建立独立小core映射，`sim`执行四模型原生网表整数检查。没有接口布局、引脚下载或硬件访问。

这些是模块级验证；完整720p、三输出bank、真实DDR并发、整机时序/电气及板上FPS必须由对应的新整机证据确认。
