## 2. 操作方式

使用已确认的Ti60F225I3 DemoBoard V4、SC431HAI配套模组/J4，J2/J3沿用2–3。接口及供电不更换，J8不是UART。

用Efinity Programmer的JTAG模式临时下载上面的 `.bit`。本轮没有代为下载，也没有改Flash；不需要在本轮做SPI固化。

按键仍保持原来的四风格操作，新的“按键选显示、手势选风格”还没有接入这个bit：

| 操作 | 功能 |
| --- | --- |
| 启动 | 先显示原图，真正1280×720，不是VGA放大 |
| KEY0 | 梵高 |
| KEY1 | 剪纸 |
| KEY2 | 漫画 |
| KEY3 | 水墨 |
| KEY1+KEY2约0.5秒 | 回到原图 |
| KEY0+KEY3约1秒 | 逻辑复位 |

模式在整帧作业开始锁存，忙中切换等当前完整作业结束。组合键按下初期仍可能产生一次单键请求，随后以组合操作为准。原画复制不计入I，因此启动原画时I00正常；按KEY0等选择风格后再观察推理计数。

板载UART仍只读输出115200/8N1的 `@CAM3`，使用 [camera_view.py](../pc/camera_view.py)：

```powershell
python F:/fpga_qiansai/elinx/projects/camera_art_styles/pc/camera_view.py --list
python F:/fpga_qiansai/elinx/projects/camera_art_styles/pc/camera_view.py --port COM31
```

COM31是示例，选择实际端口，先关闭占用该端口的软件；工具不发送图像或控制命令，Ctrl+C停止。

## 3. 数据流和时钟

```text
SC431HAI 1920×1080 RAW10 / 4 lane
  → D-PHY5.8 / PPI原子异步FIFO / CSI-ECC-CRC及完整帧校验
  → 全视野Bayer双线性插值、横纵各取2/3
  → 1280×720 RGB565 / DDR三个原图槽
  → CPU锁定最新完整源帧、已加载模型身份、启动DMA
  → 两条672×720（核心640、左右halo16）
  → 六通道五层RF33 / 逐层reflect101 / 量化卷积激活及折叠BN
  → 输出槽0/2/10MiB / 全部像素及最后真实DDR B
  → 两项完整帧队列 / 计算与显示解耦
  → 读事务排空、FIFO刷新、受保护消隐提交
  → 1280×720p60 / C、I、H叠加
```

UI/CPU为100MHz，CNN为166.667MHz，DDR PHY仍400MHz，HDMI为74.25/371.25MHz。外部时钟、电平与原720p签核版逐字节相同。CNN像素通过两组24位异步FIFO，参数/起点通过稳定数据请求ACK跨域；最后实际配置ACK之前禁止START。

RAW最早像素在低10位；DDR按行RGB565、小端，每128位最低16位为最早像素。CNN为低8位R、中8位G、高8位B。激活uint8、权重int8、int32累加/偏置，原舍入与0–255饱和保持。归一化为冻结BN折叠，不是运行时IN。

## 4. 主要模块和接口变化

| 模块 | 实现和接口重点 |
| --- | --- |
| `video_system_fps_srl` | 新整机连接；源池仍三个槽，输出目标和待显示目标分别用2位 `output_bank`、`commit_bank` |
| `fps_cnn5_srl` | `3→6→6→6→6→3`，dilation1/1/2/4/8，33×33感受野；前四层6输出通道并行，末层3输出通道并行 |
| `fps_conv3x3_srl` | 与已验证C6运算相同，只改变权重存储；保留逐通道固定位置偏置写入修复 |
| `fps_srl_weights` | 每8字一银行的顺序SRL；必须完整升序加载，不能当任意地址RAM使用。当前APB逐项地址检查和固件365项序列满足该要求 |
| `fps_line_ram` | 最多1024深的多银行行历史，单拍同步读、使能保持、同地址读写返回旧数据 |
| `fps_tile_engine_3bank_srl` | 两条带完整输出；128位AXI读突发16拍、写单拍，最终B后 `done`，读写错误整帧不发布 |
| `video_control_apb_fps` | 每风格365项，地址仍为kind/layer/word/chunk；忙时拒绝改权重，cfg跨域ACK和完整计数后才允许提交模型 |
| Sapphire / 私有C固件 | 9692字节，原SC431HAI ID/163项表/曝光限制/安全失败/PLIC IRQ16保留，四组365项学习参数动态加载 |
| `video_job_control_fps` | 三输出槽、两项有序完整帧队列；计算完成IRQ可早于显示ACK，旧前台只在晚ACK后归还 |
| `frame_reader_fps` | bank0/1/2→0/2/10MiB，拒绝3；排空旧读、清FIFO并等两域busy退出，且仍在安全消隐才ACK |
| `pixel_fifo_fps` | 深度512保持；明确10位原厂存储计数零扩展成11位；真实读域busy接reader两级同步 |
| `axi_write_pair_fps` | 两主各一个在途，总计两个；AW/W成对保序，同ID0响应队列路由真实B，禁止提前ACK |

原图槽为4/6/8MiB，输出槽为0/2/10MiB，每帧1843200字节，不重叠。当前DDR配置14 row、10 column、3 bank、16-bit，10MiB槽位在其地址范围内；没有改变DDR参数。后续三模式显示若增加原图引用槽，必须统一重新规划地址，不能再把10MiB分给原图。

三输出槽的关键是区分正在计算、完整待显示、正在显示。`engine_done`是全像素及最终B完成契约；`commit_ack`则表示旧显示读事务与FIFO已排空，二者不能混用。详见 [reader和调度](fps_reader.md)、[写事务优化](fps_write_pressure.md)。

## 6. 哪些帧率是真正测过的

| 范围 | 结果 |
| --- | --- |
| 原十二通道完整720p CNN/DMA模型 | 1.881229fps |
| 新SRL RF33梵高完整720p CNN/DMA | 921600像素误差0、6007407个100MHz UI周期，16.646117fps |
| 三缓冲实际jobs/reader/FIFO/raster＋固定引擎延迟模型 | 6次完成间隔6007412–6007418周期，额外调度5–11拍；19完整显示帧逐值通过 |
| 当前实板采集/推理/显示并发 | 尚未运行本bit，无真实FPS结论 |

同范围CNN/DMA模型约快8.85倍。新完整SRL测试确实写第三输出bank，含真实异步FIFO、有界AXI及最终B；不是只将小尺寸周期乘面积。四模型新SRL RTL和原生网表也分别逐值验证，完整720p只实跑梵高一个模型。

共享写压力证明新仲裁能改善延迟容忍，但最慢的合成服务点仍不可持续；真实DDR可能限制在途接受能力，真实采集/显示读也会竞争。因此**不能把16.646模型成绩直接写成实板稳定超过15fps，不能称整题已完成**。

上板应记录C/I/H、累积采集与推理完成帧、捕获/显示错误、持续运行时长和画质。C为完整采集、I只计真实CNN完成、H60为显示刷新配置；原画复制和重复显示不计I。要证明稳定超过15fps，应按至少数十秒的完整新帧累计差计算，不能只看某一秒I16。

后续手势仅1–4、持续四个完整一秒窗口、只在原图/对比界面识别；按键改成三种显示内容另行集成。当前仅四秒门控模块独立测试通过，本bit没有图像手势识别器或左右对比界面。
