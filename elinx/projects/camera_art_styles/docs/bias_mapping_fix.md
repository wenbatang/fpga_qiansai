# CAM3纯色故障：偏置写入的综合映射修复

2026-10-23。当前发布为 `build/camera_bias_fix60/`，四模型映射后数值检查与整机CAD/电气/CDC签核均已PASS，已生成bit，未代为下载。保留此前所有工程、demo V7/V9和四组学习参数。

## 实板证据

用户在放大版继续看到异常，反馈原画可辨识、略偏绿。真实CAM3中启动B3，捕获2634、推理148、捕获错误0；CSI control/header/format/CRC/FE/timeout等分项0，SoT仍记录。`view_mode=0x14`为剪纸风格1、请求/已加载均1、引擎和已提交均非原画。

两个统计像素数均307200。原图RGB均值为15.999844/16/15.999870，输出恰为8/125/74。源和输出是不同时间的快照，没有绑定同一帧；均值本身不能证明所有像素恒定。

冻结整数网络对RGB16输入的剪纸输出为RGB142/95/85，RGB565展开后140/93/82。最后一层若只有偏置、没有卷积贡献，量化RGB为11/126/77，RGB565展开后正好8/125/74。这个对应关系指向CNN内部数值问题，需要进一步验证，不能只凭一条日志就判定权重全零。

## 已复现的数字错误

独立 `build/cnn_map_probe/` 对原 `video_cnn_tile5` 和 `video_conv3x3` 做真实Efinity2026.1.132综合，使用安装包原生EFX RAM/DSP/FF/LUT行为模型，和同输入/运行时权重的原RTL逐拍对照。

- 96×64、RGB16、剪纸：RTL输出低字节R的24位数据`555f8e`，网表输出`4d7e0b`，还原RGB565就是实板统计中的8/125/74。旧长仿真在获得这些错误后手动停止，保留失败日志，**不记为完整帧通过**。
- 首层最早开始分歧，进入第二层的特征已经不同。输入采样和逐拍读取权重一致。
- 独立短探针读取组装寄存器与权重RAM首字，原RTL和网表一致；探针为检查而强制读地址/读使能，不是运行时板上读回。
- 首层首组读出的偏置为网表`0000116c00000fc1fffff223`、RTL`000015f600001281fffff223`；第0通道一致，第1/2通道错位。逐拍偏置、乘积、采样、权重和各层输出的日志保留在 `sim/cnn_mapped/`。

因此，至少已确认一处**当前工具链对动态偏置写入的综合映射与RTL不一致**。这个已复现的数字错误独立于训练目标和HDMI显示尺寸。RISC-V的1217次计数只证明接收了配置事务及顺序，不能证明偏置经过综合后落在正确通道；此前仅检查RTL数值和CAD时序，漏掉了这项映射后数值检查，本轮已经补上。本地失败回执为`sim/cnn_mapped/reproduction.json`，其结果明确为`REPRODUCED_MISMATCH`，不能将它计入通过的回归。

## 修复范围

原写法同时使用运行时数组索引与运行时位段索引：

```verilog
biases[cfg_address[10:0]/LANES][(cfg_address[10:0]%LANES)*32+:32] <= cfg_data;
```

新 `rtl/bias_fix/video_conv3x3_fixed.sv` 为每个输出通道生成一个固定译码器；每个32位偏置位置只有一个常量索引写入者。偏置地址协议、32位补码、流水读取、卷积乘加、量化/饱和、权重和帧尺寸全部保持。通过静态还原比较约束，除模块名和该写入块外必须与原卷积逐字一致。

集成变体只改模块名引用，固件仍为原25032字节，四组各1217写入、Boot RAM、传感器寄存器、PPI恢复、Bayer、DDR、显示行缓存、960×720视口、CAM3、四键/原画切换、PLL和整份peri均不改。原文件不覆盖，旧bit只作历史证据保留。
