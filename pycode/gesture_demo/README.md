# 主机摄像头手势与风格预览

本程序使用电脑 USB 摄像头，在电脑上检测手部关键点、确认手势并显示四种网络风格。不会访问 FPGA、打开串口、写 Flash、上传或保存摄像头照片。当前用户已实际确认画面正常，1–4可保持4秒确认；随后针对中国式“三”放宽了自然弯拇指的判定，仍需现场复测该姿势。

## 启动与停止

在 `F:\fpga_qiansai` 的 PowerShell 中运行：

```powershell
& '.\pycode\gesture_demo\.venv\Scripts\python.exe' -B '.\pycode\gesture_demo\launch.py' --autostart
```

界面可选择摄像头编号，按“开始采集”打开；“停止并释放摄像头”停止工作线程并释放设备；关闭窗口也会先释放设备。当前实测设备为 EMEET SmartCam C960 2K、编号0。若被其他应用占用，先关闭占用程序。

`launch.py` 经本地 Windows 桌面兼容启动器打开自己的 GUI。这修复了从 Codex 打包进程直接启动时摄像头 COM/DLL 查找失败的问题，不修改驱动或隐私设置。代码入口为 `app.py`，普通终端也可直接运行它。

## 操作

| 操作 | 效果 |
|---|---|
| 原图按钮 / 空格循环 | 摄像头原图 → 转换后 → 左原右风格 |
| 手势1 | 梵高 |
| 手势2 | 剪纸 |
| 手势3 | 漫画；可伸拇指＋食指＋中指，也可伸食指＋中指＋无名指 |
| 手势4 | 水墨；拇指收起、其余四指伸出 |
| 数字风格按钮 / 左右方向键 | 手动选择风格 |
| 复位演示 | 回原图、默认梵高，清除手势资格 |

只在**原图或左右对比**界面识别手势；“转换后”暂停识别。在原图界面确认风格后仍显示原图，点击“转换后”或“左原图＋右风格”才看到风格效果。

只举一只完整的手，掌心朝镜头，尽量让手占画面较大区域。绿色骨架表示检测到手；顶部显示数字、判定原因和4秒进度。保持同一明确数字连续4秒，按1秒窗口确认：t0、t1、t2、t3、t4五次新采样。识别中断、数字改变、帧间隔超过0.4秒或切入风格界面都会清空计时。确认后先把手移开至少0.5秒，再做下一次选择；持续举手或直接换数字不会重复触发。

如果显示“0只手”，先检查完整手部是否入镜与照明；有骨架但数字为“—”说明姿势未分类。中国式三允许拇指自然弯曲，但应明显向掌外展开，避免和二混淆。画面镜像只影响预览，规则使用三维骨架距离与角度。

## 模型和性能边界

优先加载 `pycode/painterly_style/runs/paint_final/model.pt`；不存在时使用保留的 `full720_style/runs/c6_v1/model.pt`。训练结束后停止、再开始采集会加载最终模型。底部显示实际模型路径和训练步数。没有模型时只提供摄像头/手势。

源图在本机转 RGB565 再展开后送网络，接近 FPGA 输入量化；左右对比由同一张采集帧合成。主机显示帧率包含主机计算开销，不能作为 FPGA 的帧率。这里没有将识别结果发给板卡；新硬件版本只集成显示模式与按键。

## 依赖与自测

隔离环境 `.venv` 的依赖见 `requirements.txt`。手部模型只在首次准备时由 `setup_model.py` 从官方地址下载，之后离线运行。模型为 MediaPipe Hand Landmarker，返回21个关键点；手势数字由本项目规则判断，4秒确认由独立 `HoldGate` 管理。参考：[官方 Python 接口](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)。

`sim/check_gestures.py` 覆盖75个合成骨架变换和8类时间门控场景；这是规则回归，不等于真实用户准确率。`build/live_status.json` 只记录数字诊断/时间/事件；`build/last_session.json` 记录采集计数与错误，不保存图像。
